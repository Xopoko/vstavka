# Reporting security issues

Report vulnerabilities privately through **Security → Report a vulnerability** on
this GitHub repository. Include the Vstavka version, which app you use (the
Microsoft Store app or the cross-platform app), your operating system and its
version, and the impact. Use synthetic clipboard content in reports. Do not
attach a real `history.vstavka` file, screenshots of your own history, or copied
passwords and tokens.

## What Vstavka protects

Vstavka stores clipboard history and settings in your user profile (the
[README](README.md#privacy) lists the folders) and encrypts them at rest:

- **Windows:** Windows Data Protection (DPAPI) for the current user.
- **macOS:** AES-256-GCM with a random key kept in the login Keychain.
- **Linux:** AES-256-GCM with a random key kept in the Secret Service, usually
  GNOME Keyring.

This protects the history file from other user accounts and from copies taken
off the computer. It does not fully protect history from programs running under
your own account: on Windows they can decrypt it the same way Vstavka does, and
on Linux any app in your session can ask the Secret Service for the key. On
macOS the Keychain asks you before another app reads the key. When no key store
is available, the cross-platform app keeps history in memory only.

Vstavka has no network code, accounts or telemetry. It skips clipboard content
while saving is paused, content from apps in the exclusion list, and content
that apps mark as private:

- **Windows:** the formats `ExcludeClipboardContentFromMonitorProcessing` and
  `Clipboard Viewer Ignore`, or `CanIncludeInClipboardHistory` set to zero.
- **macOS:** the [nspasteboard.org](http://nspasteboard.org/) markers
  `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType` and
  `org.nspasteboard.AutoGeneratedType`, plus older markers used by some
  password managers and text expanders.
- **Linux:** `x-kde-passwordManagerHint` set to `secret`, and the private
  types used by KeePassXC and GNOME.

## The GNOME Shell helper

On GNOME Wayland, apps cannot watch the clipboard, place their windows or send
keystrokes, so the cross-platform app uses a GNOME Shell extension for these.
The extension answers only executables listed in its `allowed-executables`
setting, checked through `/proc/<pid>/exe`, and one client at a time. This keeps
ordinary programs from reading the clipboard through it, but it is not a
sandbox: code already running as you can change the setting or start an allowed
executable. See the [extension README](gnome-extension/README.md) for details.

Reports are most useful when they show clipboard content that should have been
skipped, history that outlives deletion or retention, data leaving the
computer, a way for another user account to read the history, or a program that
is not allowed but can still use the GNOME helper.
