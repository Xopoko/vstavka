# macOS adapter

Construct `MacPlatformServices` on macOS and start the monitor on the Avalonia UI synchronization context. Native clipboard and window operations run on the AppKit main thread. The monitor starts from the current `changeCount` and polls at 300 ms. Later copies supersede earlier ones between ticks. Source name, bundle ID, and icon describe the foreground app at detection time, which can differ from the writer if focus changed. Source icons are rendered in a 32 × 32 bitmap and capped at 64 KiB.

## Clipboard privacy

The monitor skips `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, and `org.nspasteboard.AutoGeneratedType` before reading payloads. It also skips the legacy 1Password marker `com.agilebits.onepassword`, `de.petermaurer.TransientPasteboardType` from TextExpander and Butler, `com.typeit4me.clipping`, and Typinator's `Pasteboard generator type`. [NSPasteboard marker conventions](https://nspasteboard.org/)

`Permissions` reports `clipboard-access` as required. macOS releases before the 15.4 pasteboard access API allow background reads. With the API, background capture requires `AlwaysAllow`. The monitor checks new changes without opening the payload or requesting access in `Default`, `Ask`, or `AlwaysDeny`. The next copy after approval is eligible. Requesting access from `Default` or `Ask` makes one user-initiated read of plain text from the general pasteboard and discards the result. This triggers the system access alert and lists Vstavka in Clipboard settings. In `AlwaysDeny`, the request opens Privacy & Security → Clipboard. Permission states are read from macOS each time the UI queries them. [Apple's pasteboard access modes](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum/default?language=objc)

The adapter prefers file URLs, then PNG or TIFF, then URL and plain text. Finder file URLs are stored as paths. TIFF is decoded by AppKit and converted to PNG if it fits the pixel and byte limits. The writer prepares representations before taking the clipboard and records the exact count from `clearContents` for suppression. A plain-text replay writes a single string, with newline-separated paths for file entries.

## Hotkey, panel and paste

The default shortcut is `Shift+Meta+V` (⇧⌘V). The other suggestions are `Ctrl+Meta+V` and `Alt+Meta+V`. The adapter registers usable `HotkeyGesture` combinations through Carbon. Ctrl is Control, Alt is Option, Shift is Shift, and Meta is Command. Letters A–Z and digits 0–9 use physical ANSI US keyboard positions. F1–F20 and Space are supported. F21–F24 are unsupported. A replacement is registered before releasing the current shortcut.

The panel uses the status window level and `canJoinAllSpaces | fullScreenAuxiliary` so a single window can join the active Space, including a full-screen Space. Activation and keyboard focus still depend on the system and the packaged app's activation policy.

Call `CaptureTarget()` before showing the panel and `PasteAsync()` after hiding it and writing the clipboard. The adapter waits up to 500 ms for the retained target app to become frontmost before posting Cmd+V. `Permissions` reports `accessibility` as optional and reads trust from `AXIsProcessTrusted()`. The first request in a process invokes the system Accessibility prompt. Subsequent requests open Privacy & Security → Accessibility. Clipboard replay remains available for manual paste.

The Mac App Store build (`-p:VstavkaMacAppStore=true`) puts the chosen item on the clipboard and returns focus to the previous app for a manual Cmd+V. Its onboarding asks only for clipboard access. Start at login is opt-in, and Settings contains a link to the privacy policy.

The Mac App Store build asks StoreKit for a rating when Settings closes with the panel hidden, after at least ten successful clipboard picks outside onboarding and three days since the first pick. A request requires persistent history so Vstavka can save the requested app version and ask at most once per version. StoreKit decides whether to show the prompt.

## Start at login

Packaged apps on macOS 13 and later use `SMAppService.mainAppService`. Only `Enabled` counts as enabled. `RequiresApproval` means the user needs to enable the item in System Settings → General → Login Items & Extensions before it can run at sign-in. [Apple's Service Management documentation](https://developer.apple.com/documentation/servicemanagement/smappservice?language=objc)

## History

History data lives in `Library/Application Support/Vstavka`, under the user's home for the preview or inside the app's container for the Mac App Store build. The adapter checks the login Keychain on first use for a generic password with account `history-key`. The preview uses service `io.github.xopoko.Vstavka` and the Mac App Store build uses `io.github.xopoko.Vstavka.AppStore`. Successful lookup or creation enables the Core AES-GCM protector. Keychain errors at initialization select in-memory history for the process.

## Diagnostics

The read-only probe prints the OS version, pasteboard access behavior, permission codes and states, and its own login-item status. A standalone probe reports `Unsupported` for the login item because it runs outside an app bundle.

```text
dotnet run --project tests/Vstavka.Platform.MacOS.Tests
dotnet publish tests/Vstavka.Platform.MacOS.Probe -r osx-arm64 --self-contained -c Release
```
